# Code Mode groups project-wide capabilities under mops

> **Status: accepted.** Amends ADR-0008 and ADR-0011.

Project-wide **Code Mode Extensions** are grouped by purpose beneath the global `mops` namespace, while extensions with a meaningful native MPS receiver remain on that receiver. Concept-specific operations also use the namespace when the native receiver type is too broad to form a useful extension surface: build-language editing operations belong under `mops.editing.build` because their native `SNode` receiver does not express the required concept. Built-in capabilities compose through nested namespace receiver types and Groovy extensions: Java parsing is exposed at `mops.parsing.java`, identity lookups at `mops.lookup`, repository searches at `mops.search`, and build-language editing at `mops.editing.build`. This keeps the global script surface small, avoids presenting a mutable service registry, and leaves room for `mops.testing` when that category gains executable behavior. A language-oriented namespace and a compatibility contract for external extension bundles are deferred until concrete capabilities require them.

Lookup operations return one object or null when the supplied identity does not resolve; ambiguity remains an error. Their `require*` variants reject a miss. Search operations discover zero or more matches for criteria within an explicit scope; exact, pattern-based, and fuzzy matching are search strategies rather than different lookup contracts.
